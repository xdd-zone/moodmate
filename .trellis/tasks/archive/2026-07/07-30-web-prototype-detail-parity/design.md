# 技术设计

## 范围

主要修改 `apps/web/src/components` 和 `apps/web/src/components/moodmate/moodmate.css`。不修改 API、数据库、contracts、Admin、共享主题包或路由结构。

原型在浏览器中的实际渲染是视觉依据；真实 API 与现有路由是功能依据。两者冲突时，保留真实功能，通过展示层补齐原型状态。原型 class 名与实际渲染冲突时，不根据 class 名猜测设计意图。

## 共用组件

- 扩展头像菜单触发器，使导航栏用户头像、聊天头朋友头像和消息头像复用同一套点击、右键、边界检测、滚动关闭和 Escape 行为。
- 扩展信息栏头部，允许单聊和群聊传入操作按钮，不把业务按钮写死在共用组件里。
- 提取聊天输入状态和消息操作的共用展示，单聊与群聊使用同一套三点动画、复制按钮和日期分隔样式。
- 保持 Web 专用组件在 `apps/web`，不移动到 `packages/ui`。

## 聊天数据

- 单聊保留 `useChat` 与现有流式传输。
- 在前端消息展示模型中保留 `createdAtMs`，历史消息直接来自合同；本地新消息在发送时记录当前时间，服务端刷新后以合同值为准。
- 日期分隔按消息本地日期计算，只在相邻消息跨日时插入。
- 连续消息只在相邻消息发送者相同且没有跨日时收起重复头像。
- 复制只调用浏览器剪贴板，不新增接口；复制失败时不阻断聊天。
- 单聊生成状态和群聊发送等待状态驱动标题下方输入动画与消息区三点气泡。

## 静态控件边界

- 表情、附件、静音、群设置和资料编辑等缺少合同的能力只还原视觉状态，使用 disabled 控件或明确的现有页面入口，不发起无效请求。
- 不把示例统计写入后端，不用静态数值覆盖真实消息数量。
- 登录、朋友 CRUD、群聊成员操作、记忆和主动关怀继续调用现有接口。

## 主题

- 继续使用 `ThemeScript`、`ThemeToggle`、`moodmate-theme:v1`、`latte` 和 `mocha`。
- 设置页主题预览卡改为选择控件，调用现有主题 API，不引入 `light` / `dark` 第二套状态。
- 登录页只调整欢迎内容纵向定位，不改变标题字号、字体和主题持久化。

## 响应式

- 1100px 默认隐藏信息栏并由头部按钮打开右侧抽屉，820px 收窄列表，640px 进入单列并使用全屏资料视图，继续作为应用壳基线。
- 保留当前为真实长内容添加的 760px、420px 和低高度规则，只修复与原型基准视口冲突的样式。
- 在 1440x900、1280x720、820x900 和 390x844 检查每个页面；移动端必须保留返回列表或页面导航入口。
- 朋友档案的统计区按原型实际渲染使用纵向通栏卡，不补写原型缺失的三列网格规则。

## 回退点

- 聊天展示模型与 `useChat` 集成是风险最高的改动，先保持发送、停止、历史分页和反馈逻辑不变，再补时间与分组。
- 信息栏和设置面板只做可局部回退的组件改动。
- `moodmate.css` 按页面分区修改，避免全局 token 变更影响所有页面。
