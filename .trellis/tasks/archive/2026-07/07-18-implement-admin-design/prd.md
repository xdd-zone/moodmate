# 实现 MoodMate 后台设计稿

## 目标

把 Open Design 项目 `68eedb2d-69da-46ab-94d4-971a9ba8c6b1` 的“情绪记录”后台范式页接入现有 `apps/admin`，保留设计稿的信息层级、紧凑布局、主题风格和主要交互，同时保持现有 Next.js 16 + React 19 工程可运行。

## 已确认事实

- 设计源只有 `admin-console.html` 及版本记录，没有 `DESIGN.md`、README、`package.json` 或独立素材文件。
- 设计页包含侧栏、顶栏、统计卡、今日情绪分布、筛选表格、批量选择、详情抽屉、组件规范折叠区和 Latte/Mocha 主题切换。
- 现有管理端已经实现管理员登录、会话恢复、概览页和角色管理页，使用 Next.js App Router、Tailwind CSS 4、`@repo/ui` 和 Maple Mono。
- 现有 API 没有情绪记录列表和统计接口。设计源里的记录、统计和用户信息都是演示数据。
- 设计源没有位图或其他外部素材，视觉主要由排版、颜色、图标、表格和状态组件构成。

## 需求

1. 在现有管理端新增 `/moods` 页面，不替换 `/` 概览页和 `/roles` 角色页。
2. 公共管理壳升级为设计稿的侧栏与顶栏结构，并保留现有退出登录和主题切换能力。
3. `/moods` 复现设计稿的统计卡、情绪分布、筛选工具栏、记录表格、批量选择、分页外观和详情抽屉。
4. 实现关键词筛选、情绪分段筛选、行选择、全选、详情打开与关闭、Escape 关闭、组件规范折叠和主题切换。
5. 本次是纯 UI 实现。演示数据只保存在前端组件中，不新增或修改 API、BFF、contract、数据库、鉴权、登录和角色接口。
6. 使用现有 Catppuccin 语义 token、Maple Mono 和共享 UI 原语；页面组件不直接写固定主题色值。
7. 桌面端保持设计稿的信息密度；移动端提供可操作的导航、表格横向滚动和不重叠的抽屉布局。
8. 交互元素保留 `focus-visible`，支持键盘操作和减少动态效果模式。

## 验收标准

- [x] 打开 `http://localhost:6154/moods` 能看到与 `admin-console.html` 同构的情绪记录管理页。
- [x] `/`、`/roles`、登录和退出流程仍可使用，并共享新的管理壳。
- [x] 关键词和情绪筛选会更新当前表格；行选择和全选计数正确。
- [x] 点击记录行或查看操作会打开对应详情，点击遮罩、关闭按钮或按 Escape 会关闭详情。
- [x] Latte 和 Mocha 切换后页面文字、边框、状态颜色清晰，刷新后主题保持。
- [x] 1440px 桌面视口和 390px 移动视口没有文字、按钮、表格工具栏或抽屉相互遮挡。
- [x] `pnpm check-types`、`pnpm lint` 和 `pnpm --filter admin build` 通过，本次改动文件通过 Prettier 检查。
- [ ] 完整仓库 `pnpm format:check` 通过。当前被 3 个未修改的原有文件阻塞：`.trellis/tasks/archive/2026-07/07-17-admin-ui-revamp/task.json`、`.trellis/workspace/喜东东/index.md`、`.trellis/workspace/喜东东/journal-1.md`。

- 任何现有接口、请求函数、响应类型和服务端路由调整。
- 导出 CSV、手动补录、编辑、删除、推送关怀等服务端动作。
- 用户管理、内容管理和系统设置页面的业务实现。
