# 实现 Agent 记忆系统

## 目标

为 Moodmate 的聊天功能增加服务端记忆。用户重新打开页面后可以恢复历史消息，继续聊天时模型可以使用最近消息、会话摘要和长期记忆，用户可以查看和管理系统保存的长期记忆。

## 背景

- 当前聊天记录只保存在 `useChat` 的页面状态中，刷新后会丢失。
- 当前 API 只接收前端传入的最近 20 条消息，没有服务端会话、消息历史或长期记忆。
- 当前产品只有一个固定的 `MoodMate` 伴侣，没有 Agent 数据表、Agent 管理页或多 Agent 会话列表。
- 课程参考项目 `/Users/wuwanzhu/Code/bobo/ai-agent` 的记忆功能按用户与自建 Agent 隔离，不能原样复制到当前数据模型。
- 本任务按 Moodmate 的固定伴侣形态实现 41-46 节能力，不补建课程项目的多 Agent 系统。

## 需求

### R1. 聊天历史

- 用户消息必须在调用 LLM 前保存，模型请求失败时仍能恢复该消息。
- assistant 回复必须在文本流结束后保存，不得取消现有流式输出。
- 页面打开时从服务端恢复最近 40 条消息。
- 用户可以按时间游标加载更早消息。
- 每次历史读写必须限制为当前登录用户的数据。

### R2. 三层记忆

- 短期上下文使用服务端保存的最近 18 条消息。
- 中期上下文使用会话滚动摘要，规则摘要最多保留 1600 个字符。
- 长期记忆保存类型、内容、重要度、状态、来源消息和时间。
- 聊天 prompt 按系统规则、长期记忆、会话摘要、最近消息、本轮输入的顺序组装。

### R3. 长期记忆提取

- assistant 回复成功后，从本轮用户输入中按关键词规则提取候选记忆。
- 单轮最多写入两条候选记忆。
- 内容完全相同的有效记忆不得重复写入。
- 记忆提取失败不得中断或撤销聊天回复。

### R4. 记忆管理

- 用户可以查看自己的长期记忆及来源消息。
- 用户可以修改记忆类型、内容、重要度和启用状态。
- 删除使用软删除，删除后的记忆不再展示，也不参与 prompt。
- 页面必须提供加载、空数据、请求失败和操作中状态。

## 约束

- 使用现有 D1、Drizzle ORM、Hono、Zod、TanStack Query 和 AI SDK 技术栈。
- 请求和响应结构统一定义在 `packages/contracts`。
- 不引入向量数据库、embedding、LLM 结构化抽取、多会话列表或群聊记忆。
- 不改变本地 LLM 配置优先、平台 DeepSeek 配置备用的现有行为。
- 保留现有未提交文件，不修改其他 Trellis 任务。

## 验收条件

- [ ] 刷新聊天页后，已保存的用户消息和 assistant 回复按时间顺序恢复。
- [ ] 没有历史时显示现有 MoodMate 默认空状态或开场内容，不插入伪造的历史记录。
- [ ] 超过首次返回数量后，可以加载更早消息，且不会改变消息顺序。
- [ ] 发送新消息时，服务端使用已保存历史、摘要和启用的长期记忆组装 prompt。
- [ ] 模型请求失败后，刚发送的用户消息仍保存在历史中。
- [ ] assistant 流结束后，会话消息数、摘要和最近消息时间得到更新。
- [ ] 符合规则的用户偏好或边界可以写入长期记忆，完全相同的内容不会重复写入。
- [ ] 用户可以查看、编辑、启用、停用和软删除长期记忆。
- [ ] API 无法读取或修改其他用户的会话、消息和记忆。
- [ ] `pnpm check-types`、`pnpm lint`、`pnpm format:check` 依次通过。

## 不包含

- 创建或管理多个 Agent。
- 一个伴侣对应多段独立会话。
- 群聊或多 Agent 记忆。
- 记忆确认状态、语义去重、向量检索和数据恢复界面。
