# API D1

## 1. 适用范围

新增或修改 `apps/api` 的 D1 binding、基础查询、readiness、migration 或开发 seed 时使用本规范。业务表查询仍由所属模块 repository 负责。

## 2. 签名

```ts
checkD1Readiness(database: D1Database | undefined): Promise<void>;
getReadinessStatus(bindings: ApiBindings): Promise<ReadinessResponse>;
```

HTTP 接口：

```text
GET /health                 # liveness，不访问 D1
GET /rpc/system/readiness   # 执行 SELECT 1 AS ok
```

## 3. 合同

默认开发环境的 Wrangler binding：

```jsonc
{
  "binding": "DB",
  "database_name": "moodmate-local",
}
```

- 本地 binding 不填写伪造的 `database_id`，也不设置 `remote: true`。
- test 和 production 当前没有 D1 binding，所以 `ApiBindings.DB` 必须是可选字段。
- `D1Database` 由 `pnpm --filter api cf-typegen` 生成的 `worker-configuration.d.ts` 提供。

readiness 成功数据：

```json
{ "status": "ready" }
```

失败使用 `SYSTEM.DATABASE_UNAVAILABLE` 和 HTTP 503。客户端消息固定为“数据库不可用”，不返回数据库名、本地路径、SQL 或 D1 原始错误。

### migration 一旦被应用，改文件对已有库无效

`wrangler d1 migrations apply` 会把执行过的文件名写进 `d1_migrations` 表，之后再改那个文件，wrangler 不会重跑。库停在旧结构，代码按新 schema 查询，运行时报 `no such column: <表>.<列>`，接口 500。

按 migration 是否已经提交决定改法：

- 文件还在工作区未提交（`git status` 显示 `??`）：直接改文件，然后删掉 `d1_migrations` 里那一行、drop 该 migration 建的表、重新 apply。文件只存在于本地，不需要新增 migration。
- 文件已提交：必须新增 migration。此时改原文件只会让新环境和存量环境结构不一致——新环境一次建全，存量环境永远缺列。注意 SQLite 的 `ALTER TABLE ADD COLUMN` 加不了 CHECK 约束和外键，要还原完整约束得走建新表、拷数据、删旧表、改名。

改完用这段脚本核对库与 migration 是否一致，不要凭印象：

```bash
python3 - <<'PY'
import re, sqlite3, glob
db = glob.glob(".wrangler/state/v3/d1/miniflare-D1DatabaseObject/*.sqlite")[0]
sql = open("migrations/0016_admin_api_operations_rebuild.sql").read()
conn = sqlite3.connect(db)
for m in re.finditer(r"CREATE TABLE `(\w+)` \((.*?)\n\);", sql, re.S):
    table = m.group(1)
    want = [c.group(1) for c in re.finditer(r"`(\w+)` (?:text|integer)", m.group(2))]
    have = [r[1] for r in conn.execute(f"PRAGMA table_info({table})")]
    missing = [c for c in want if c not in have]
    if missing:
        print(f"{table} 缺列 {missing}")
PY
```

## 4. 校验与错误矩阵

| 条件                       | HTTP | 业务码                        | 服务端行为           |
| -------------------------- | ---- | ----------------------------- | -------------------- |
| `DB` 存在且查询结果为 `1`  | 200  | 无                            | 返回 `status: ready` |
| `DB` binding 缺失          | 503  | `SYSTEM.DATABASE_UNAVAILABLE` | 记录原始错误         |
| D1 查询抛错                | 503  | `SYSTEM.DATABASE_UNAVAILABLE` | 记录原始错误         |
| 查询完成但结果不是数字 `1` | 503  | `SYSTEM.DATABASE_UNAVAILABLE` | 记录原始错误         |
| `/health` 请求且 D1 不可用 | 200  | 无                            | 不访问 D1            |

## 5. 正常、基础、错误案例

- 正常：默认开发环境启动 `pnpm dev:api`，readiness 返回 HTTP 200 和 `status: ready`。
- 基础：还没有业务表时用 `SELECT 1 AS ok` 验证 binding，不创建占位表或无效 migration。
- 错误：为了消除命名环境的 Wrangler warning 而创建远程 D1、填写伪造 ID，或让 `/health` 依赖数据库。

## 7. 错误与正确写法

```ts
// 错误：route 直接写 SQL
app.get("/rpc/system/readiness", async (c) => {
  await c.env.DB?.prepare("SELECT 1").first();
  return c.json({ status: "ready" });
});

// 正确：route 调 service，SQL 留在 infra
app.get("/rpc/system/readiness", async (c) => {
  const result = await getReadinessStatus(c.env);
  return c.json(buildSuccess(result, createMeta(c.var.requestId)));
});
```

确定首张业务表后运行 Wrangler 原生 migration 命令，让 Wrangler 创建 `apps/api/migrations/`。出现本地联调数据后再创建 `apps/api/dev/seed.sql`，执行命令必须带 `--local`。

## 8. 场景：Admin 认证数据层

### 8.1 适用范围

修改认证表、Drizzle schema、session/refresh repository、rotation trigger 或本地认证 seed 时使用本节。Wrangler 是唯一 migration 工具；不要加入 `drizzle-kit` 或 `__drizzle_migrations`。

### 8.2 签名

```ts
createD1Client(database: D1Database | undefined): DrizzleD1Database;

createSessionWithRefreshToken(
  database: D1Database | undefined,
  input: CreateSessionInput,
): Promise<void>;

rotateRefreshToken(
  database: D1Database | undefined,
  input: RotateRefreshTokenInput,
): Promise<{ status: "rotated" } | { status: "rejected" }>;

revokeSession(
  database: D1Database | undefined,
  sessionId: string,
  revokedAtMs: number,
  reason: string,
): Promise<void>;
```

### 8.3 合同

- migration：`apps/api/migrations/0001_create_auth_schema.sql`。
- Drizzle schema：`apps/api/src/modules/auth/auth.schema.ts`。
- 业务查询和写入：`apps/api/src/modules/auth/auth.repository.ts`。
- 本地 seed：`apps/api/dev/seed.sql`，只能通过带 `--local` 的 Wrangler 命令执行。
- Drizzle 负责运行期类型和查询，不生成或执行 migration。
- session 与首个 refresh token 使用一个 `D1Database.batch()` 创建。
- rotation 在一个 batch 中插入后继 token、标记旧 token、更新 session；旧 token 的 `used_at_ms` 必须等于后继 token 的 `issued_at_ms`。
- `refresh_tokens.parent_token_id` 的非空值唯一；trigger 检查 token 与 session 状态、session 绝对截止时间和替代关系。

### 8.4 校验与错误矩阵

| 条件                                          | 数据层结果                          |
| --------------------------------------------- | ----------------------------------- |
| DB binding 缺失                               | 抛出 `D1 binding DB 未配置`         |
| session 与首 token 的 ID 或 parent 参数不一致 | 写入前抛错                          |
| rotation 成功                                 | `{ status: "rotated" }`             |
| 旧 token 已用、撤销、过期或已有后继           | `{ status: "rejected" }`            |
| session 已撤销或过期                          | `{ status: "rejected" }`            |
| 新 token 超过 session 绝对截止时间            | trigger 中止 batch，repository 抛错 |
| `jti_hash` 或新 token ID 冲突                 | 约束错误，repository 抛错           |

上层只根据 `status` 识别正常 rotation 竞争，不解析 SQLite 错误文本。无法确认属于竞争的数据库错误继续抛出。

### 8.5 正常、基础、错误案例

- 正常：有效旧 token rotation 后只有一个后继，旧 token 的 `used_at_ms` 和 `replaced_by_token_id` 同时更新。
- 基础：同一 refresh token 的两个并发请求最多一个返回 `rotated`，另一个返回 `rejected`。
- 错误：先在 TypeScript 查询旧 token，再用三个独立 repository 调用更新；并发请求会同时通过前置查询。

### 8.6 必做检查

```bash
pnpm --filter api exec wrangler d1 migrations apply moodmate-local --local
pnpm --filter api exec wrangler d1 migrations list moodmate-local --local
pnpm --filter api exec wrangler d1 execute moodmate-local --local --file=./dev/seed.sql
```

- 从空 local state 应用 migration，检查 9 张认证表、索引、3 个 `refresh_tokens_validate_*` trigger 和 Wrangler 内部表。
- seed 连续执行两次，应用、password 方式、`admin_owner`、管理员、邮箱、密码凭证和角色绑定各保持 1 条。
- 在同一个 workerd 实例中同时调用两次 `rotateRefreshToken()`，断言一个 `rotated`、一个 `rejected`，数据库只有一个后继且没有半条记录。
- 分别验证 token 已用、token 已撤销、token 已过期、session 已撤销、session 已过期和新 token 超过 session 截止时间。
- 不要并行运行多个 Wrangler CLI 进程访问同一个 `--local` state；它们可能返回 `SQLITE_BUSY`，不能作为 rotation 竞争结果。需要隔离验证时使用新的 `--persist-to` 目录。

### 8.7 错误与正确写法

```ts
// 错误：三个调用之间没有原子边界
await markRefreshTokenUsed(oldTokenId);
await insertRefreshToken(newToken);
await touchSession(sessionId);

// 正确：repository 内部用一个 D1 batch，并由唯一索引和 trigger 拒绝竞争请求
const result = await rotateRefreshToken(database, input);
if (result.status === "rejected") {
  // service 按 refresh replay 规则处理
}
```
